说明：

- 本文记录小马 API 当前返回的上游价格，用于设计后台定价和小程序展示，不应把本文价格直接硬编码到业务代码。
- 接口返回的 `channel_groups` 是当前启用分组。实际创建任务时不能指定分组，小马会按 API Key 的渠道策略自动选择；最终扣费可能命中任务创建瞬间的分组。
- 如果某个参数选项没有出现在 `option_prices` 中，表示使用该分组基础价，无额外加价。
- 下表价格单位按小马接口金额记录；token 价格为每 100 万 token。平台最终仍应换算为自己的积分/点数。
- 金额保留到便于产品和研发判断的精度；可用 `npm run sync:xiaoma-video-pricing` 生成最新快照，但快照不会自动覆盖平台售价。

## 扣费方式规则

| 小马扣费方式 | 价格计算 | 我们后台建议类型 | 小程序展示建议 |
| --- | --- | --- | --- |
| 按次，无选项加价 | `base_price` | `fixed_per_job` | 展示固定扣费 |
| 按次，有 `option_prices` | `base_price * price_multiplier + price_addition` | `option_matrix_per_job` | 根据时长、清晰度、模式实时显示价格 |
| 按秒 | `秒数 * 每秒价格`，如果有选项则先算每秒价 | `per_second_matrix` | 时长固定时展示固定值；可选时长时切换价格 |
| 按token | 小马侧按 token 与选项倍率计算，本系统不自行计算 token 数 | `token_preauth` | 下单前展示并冻结后台配置的预扣点数，完成后不按 token 自动补扣或退款 |

## 对后台扣费设计的结论

1. 视频不能只用一个 `price` 字段。至少要支持固定按次、按次参数矩阵、按秒参数矩阵、token 预扣四类。
2. 小程序下单页不能只显示“起步价”。时长、清晰度、模式、声音开关这类会影响价格的选项，必须切换后同步展示预计扣费。
3. 单选项也要展示为固定不可选项，例如只支持 8 秒就展示“8 秒”；只支持有声/无声也展示固定状态，避免用户误解。
4. token 类模型只做预扣额度，不做本系统内 token 数量计算；预扣点数必须保守配置，任务完成后可留存小马返回的成本信息供运营复核。
5. 上游分组不可由请求指定，因此平台售价不应直接绑定某个最低分组；建议后台维护“平台售价矩阵”，上游价格只作为成本参考和预警。
