# 智能提示词补全增强设计

## 背景

当前小程序生图、生视频页已有“智能补全 / 智能优化”按钮，调用后端 `/api/v1/tasks/optimize-prompt`。现有效果偏短，只会在用户输入基础上增加十几到二十个字，不能把用户的简短想法补全成可直接用于 AI 生图或生视频的完整提示词。

本次目标不是新增实时输入联想，而是增强现有按钮：根据用户原始提示词和页面上下文，输出更完整、更具体、但不偏离原意的提示词。

## 影响范围

- 函数：后端 `optimizePrompt`、提示词系统 prompt 构建、结果解析；前端生图/生视频页调用智能补全时的参数组装。
- 接口：沿用 `POST /api/v1/tasks/optimize-prompt`，不新增接口，不改变鉴权和积分扣费链路。
- 页面：生图、生视频页继续使用原按钮，补传已有 UI 上下文。
- 配置：不新增数据库字段，不新增后台配置项。
- 文档：同步说明智能补全会读取上下文并生成更完整提示词。

## 产品原则

优先解决用户真实痛点：用户只写“赛博朋克少女”“产品宣传片”这类短句时，系统应补齐主体、场景、镜头、光影、风格、质量要求等关键要素。

不做复杂架构：不新增实时联想、不新增强度开关、不做多候选弹层。先把现有按钮做明显更聪明，降低开发和回归风险。

不改变用户意图：补全应保留主体、动作、风格和限制，不擅自加入敏感、侵权、真实人物仿冒或与原输入冲突的内容。

## 方案

采用方案 A：最小改动增强。

后端系统提示词从“优化表达”改为“深度补全”。模型需要按场景补齐内容：

- 通用：主体细节、环境背景、构图镜头、光影色彩、材质质感、氛围、质量要求。
- 生图：画面构图、镜头焦段、视觉风格、细节密度、清晰度。
- 生视频：主体动作、镜头运动、时间节奏、画面连续性、时长适配。
- 图片编辑 / 图生图 / 图生视频：强调保持主体一致，只补充需要变化的部分。

前端在调用时补传已有上下文：

- 生图：功能模式、场景、比例、风格、质量、尺寸模式、是否有参考图。
- 生视频：视频模式、参考模式、比例、时长、清晰度、音频模式、是否有首帧/尾帧/视频素材。

后端继续返回 `optimizedPrompt`、`negativePrompt`、`styleSuggestions`。如果模型没有返回 JSON，继续用现有兜底解析，避免按钮失败。

## 验收标准

- 输入短提示词时，返回内容明显更完整，不只是增加十几二十个字。
- 原始主体和意图被保留，不被改成另一个主题。
- 生图和生视频补全结果有场景差异，视频结果应包含动作或镜头运动。
- 现有接口、积分扣费、会员限制不变。
- 生图、生视频核心调用仍能通过现有构建或测试检查。

## 风险

- 更长提示词会增加文本模型 token 消耗，但只在用户点击按钮时触发，风险可控。
- 输出更丰富后，个别上游生图/生视频模型可能对过长提示词敏感，因此后端提示词应要求“完整但克制”，避免堆砌无关形容词。
- 如果后台自定义系统提示词写得很弱，可能抵消默认增强规则；本次默认把内置规则放前面，并继续拼接后台配置。
