# 智能补全提速与后台入口设计

## 背景

现有“智能补全”按钮已经增强为深度补全，会把用户短提示词补成更完整的生图/生视频提示词。下一步目标是提升点击后的响应速度，并让运营能更容易维护智能补全系统提示词。

用户明确指出：不能缓存最终补全结果。相同提示词多次点击时，用户可能是在主动寻找更满意的另一版，因此重复点击应允许产生不同表达。

## 影响范围

- 函数：智能补全模型解析、系统提示词读取、模型输入上下文构建。
- 接口：继续使用 `POST /api/v1/tasks/optimize-prompt`，不新增小程序接口。
- 组件/页面：小程序提示词输入组件增加 loading 防连点；生图/生视频页绑定 loading 状态。后台在 AI 文本能力配置附近增加智能补全提示词入口。
- 配置：不新增数据库字段。复用现有 `system_prompts` 和 `system_configs`。
- 数据库：不新增表，不做最终结果缓存。
- 部署：不涉及部署结构。
- 文档：同步 API 与开发文档，说明缓存边界和后台入口。

## 产品原则

重复点击智能补全应被视为“换一版”的潜在意图，不返回旧结果。

提速优先做无体验副作用的优化：缓存配置、减少模型输入 token、阻止误触并发、使用更适合补全的模型参数。

后台入口应贴近运营配置心智：在「系统设置 → AI 文本能力」的智能补全配置旁提供“编辑智能补全提示词”入口，复用已有系统提示词编辑能力。

## 方案

采用轻量组合方案。

1. 配置与提示词缓存  
   后端缓存 `prompt_optimize` 的功能配置、模型绑定和系统提示词，TTL 约 30-60 秒。后台保存系统提示词时清理提示词缓存，使下一次点击尽快生效。

2. 上下文瘦身  
   小程序仍可传丰富 `context`，但后端发给模型前只保留对补全有帮助的摘要字段：模式、比例、时长、清晰度、音频模式、是否有参考图/视频/音频、档位名称等。不把素材 URL、路径、fileId 等传给文本模型。

3. 快模型参数  
   智能补全模型调用默认使用较低延迟参数：限制 `max_tokens`，保持适度 `temperature`，不启用思考或联网字段。若后台模型配置已有显式 `default_params`，优先尊重配置，但后端兜底默认值应适合补全。

4. 前端防连点  
   智能补全请求进行中时按钮显示处理中并禁用，避免一次点击触发多个相同请求。请求结束后恢复，用户可以再次点击获得另一版。

5. 后台近入口  
   在「系统设置 → AI 文本能力」中为 `ai.prompt_optimize.*` 配置附近增加入口按钮，跳转到「内容管理 → 系统提示词」并筛选 `targetFeature=prompt_optimize`。如当前没有记录，编辑页可新建智能补全系统提示词。

## 不做的事

- 不缓存最终 `optimizedPrompt`。
- 不新增小程序接口。
- 不新增数据库表或字段。
- 不做多候选弹层。
- 不把图片/视频素材内容交给文本补全模型识别。

## 验收标准

- 同一提示词请求不会因为缓存固定返回同一版结果。
- 连续快速点击时，前端不会并发发出多次智能补全请求。
- 后端发给模型的上下文不包含素材 URL、路径或 fileId。
- 后端系统提示词和模型配置读取有短 TTL 缓存，并在后台保存提示词时可清理。
- 后台 AI 文本能力配置页能一键进入智能补全提示词编辑/筛选入口。
- 现有智能补全接口鉴权、会员限制、积分扣费不变。

## 风险

- 配置缓存可能让后台保存后有短暂延迟；通过保存后清缓存降低风险。
- 上下文瘦身过度可能影响补全质量；保留模式、比例、时长、素材类型和档位信息作为关键字段。
- 前端禁用按钮只防止请求中的误触，不阻止用户请求完成后再次点击换一版。
